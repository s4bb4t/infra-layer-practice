# 07 — Redis Streams через Watermill 🟡

> **Уровень 🟡 — дыры.** Адаптер почти готов, не хватает одного метода — `Subscribe`.\
> Что значат уровни — в [README задач](README.md#лестница).

## Цель

**Увидеть «почти бесплатный» адаптер.**\
Порт брокера уже есть, мост `watermillx` уже есть, у Watermill есть готовый пакет для Redis Streams. Второй брокер — это десяток строк.

**Понять, что «почти бесплатно» не значит «одинаково».**\
Код похож на RabbitMQ-адаптер, но Redis Streams устроен по-другому: это лог, а не очередь ([04-brokers, раздел 3](../docs/theory/04-brokers.md#3-две-модели-очередь-и-лог)). Одна строка настройки меняет поведение системы.

**Не дано:** `Broker.Subscribe`.

**Stream — структура данных Redis: журнал записей, куда можно только дописывать в конец.**\
Каждая запись получает id вида `1697000000000-0` — время в миллисекундах и порядковый номер ([04-brokers, раздел 9](../docs/theory/04-brokers.md#stream--лог-в-одном-ключе)).

## Что сделать

#### 1. Реализуй `Subscribe`

**Возьми за образец `rabbit.Broker.Subscribe`.**\
Шаги расписаны в комментарии `TODO(step-07)` прямо над методом в `redisstreams.go`.

**Коротко, что нужно:**

1. создать `redisstream.NewSubscriber` с `ConsumerGroup = group`;
2. выбрать `OldestId` — это главное решение шага;
3. вызвать `sub.Subscribe(ctx, b.topic)` и запустить `watermillx.Consume` в горутине;
4. зарегистрировать subscriber через `b.track(sub)`, чтобы `Close()` его остановил.

#### 2. Прогони контракт

```sh
go test -tags=integration -v ./internal/infrastructure/redisstreams/
```
