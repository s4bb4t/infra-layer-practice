# 01 — Ядро: домен, порты, use case, memory, контракт-тест 🟢

> **Уровень 🟢 — полный пример.** Весь код уже написан и работает.\

## Цель

**Понять, как устроен сервис, до того как трогать инфраструктуру.**\
Инфраструктура — это базы, брокеры, кэши. Прежде чем их подключать, нужно понять, куда именно они подключаются.

**Увидеть, где проходят границы слоёв.**\
Слой — группа пакетов с одной ответственностью: домен, use case'ы, адаптеры. Граница — правило, какой слой какой может импортировать ([00-map, раздел 1](../docs/theory/00-map.md#1-главный-тезис-слоя)).

**Разобраться, что такое порт и контракт-тест.**\
Порт — интерфейс, который приложение требует от внешнего мира. Контракт-тест — проверка, что реализация порта ведёт себя так, как он обещает ([10-testing, раздел 4](../docs/theory/10-testing.md#4-контракт-тесты)).

**Понять, почему memory-реализация — не «игрушка», а эталон поведения.**\
Memory-адаптер хранит всё в памяти процесса. Он проходит те же контракт-тесты, что и Postgres, поэтому по нему можно судить, как должен вести себя любой адаптер.

## Что дано (всё)

| Где | Что внутри |
|---|---|
| `internal/app/domain` | `Order`, статусы и переходы между ними, события |
| `internal/app/port/port.go` | все порты — интерфейсы, которые приложение требует от мира |
| `internal/app/usecase` | `PlaceOrder`, `PayOrder`, `CancelOrder`, `GetOrder` и юнит-тесты на все ветки |
| `internal/infrastructure/memory` | store (репозиторий + outbox + транзакции) и broker в памяти |
| `internal/infrastructure/contracttest` | контракты на репозиторий, транзакции+outbox, брокер |
| `internal/presentation/http`, `cmd/orders/main.go` | HTTP поверх memory |

**Use case — один сценарий работы приложения: «разместить заказ», «оплатить заказ».**\
Он содержит бизнес-логику и вызывает порты, но не знает, какая база или брокер стоят за ними.

**Outbox — таблица (здесь — срез в памяти), куда событие записывается в той же транзакции, что и заказ.**\
Потом отдельный процесс (relay) забирает события оттуда и публикует в брокер. Подробно — в [09-patterns](../docs/theory/09-patterns.md#transactional-outbox).

## Что сделать

#### 1. Запусти проверки

**Склонируй репо, запусти `make hooks`, потом `make check` — всё должно быть зелёным.**\
`make hooks` включает git-хук pre-push: перед каждым `git push` сам запускается `make check`, и сломанный код не уедет на сервер.

**`make check` — форматирование, `go vet`, линтер, unit-тесты и контракт-тесты.**\
Контракт-тестам нужен запущенный Docker: они поднимают базы в контейнерах ([10-testing, раздел 6](../docs/theory/10-testing.md#6-testcontainers-go)).

#### 2. Пройди сценарий руками

**Запусти сервис `make run` — он слушает `localhost:8080` и хранит всё в памяти.**\
Остановишь процесс — все заказы пропадут. Для знакомства это нормально.

**Пройди по шагам:**

1. `POST /orders` — создать заказ;
2. `GET /orders/{id}` — посмотреть его;
3. `POST /orders/{id}/pay` — оплатить;
4. ещё раз `POST /orders/{id}/pay` — должен быть ответ `409`.

```sh
curl -s -X POST localhost:8080/orders \
  -d '{"customer_id":"alice","items":[{"sku":"book","qty":1,"price_cents":1500}]}'
curl -s localhost:8080/orders/<id>
curl -s -X POST localhost:8080/orders/<id>/pay
curl -s -i -X POST localhost:8080/orders/<id>/pay   # HTTP/1.1 409 Conflict
```

**`409 Conflict` — HTTP-код «запрос противоречит текущему состоянию ресурса».**\
Оплаченный заказ нельзя оплатить второй раз: домен запрещает этот переход.

#### 3. Сломай и почини

**Сломай memory store так, чтобы упал ровно один контракт-тест — например, убери проверку версии.**\
Так ты увидишь, что контракт действительно ловит нарушение обещания, а не просто «что-то проверяет».

**Убедись, что падает именно ожидаемый тест, и верни как было.**\
Если упали несколько тестов — посмотри почему: значит, твоё изменение нарушило больше одного обещания.

```sh
go test -v -run 'Contract' ./internal/infrastructure/memory/
```

#### 4. Добавь правило в домен

**Добавь в `domain` и `usecase` одну мелочь по выбору, с тестами:**

- «нельзя отменить заказ старше N дней»;
- или «максимум 50 позиций в заказе».

**Бизнес-правило живёт в домене, а не в HTTP-обработчике и не в базе.**\
Тогда оно работает одинаково при любом адаптере и проверяется unit-тестом без контейнеров.

> Для правила со временем пригодится порт `Clock`: в тесте время подставляется вручную, и тест не зависит от того, когда его запустили.
