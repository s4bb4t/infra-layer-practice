# Документные базы: MongoDB

**Роль:** источник истины, когда данные естественно ложатся в документы.
**Отвечает на вопрос:** как хранить агрегат целиком одним куском и читать его одним запросом.

## Когда брать

- Агрегат читается и пишется целиком (заказ со своими позициями), а связей между агрегатами мало.
- Форма данных действительно разная у разных документов (каталог товаров с разными атрибутами у разных категорий).
- Нужно горизонтальное шардирование «из коробки» и команда готова его эксплуатировать.

## Когда не брать

- Много связей и запросов «через» сущности → реляционная база: `$lookup` — это не JOIN по удобству и скорости.
- Нужны сложные транзакции между многими документами постоянно — они есть, но дороже и с ограничениями.
- «Не хотим думать о схеме». Схема всё равно есть — просто она размазана по коду и неявна. Ошибки схемы переезжают из миграций в продакшен.

## Mongo vs Postgres + JSONB

Частый реальный выбор — не «Mongo или SQL», а «Mongo или Postgres с JSONB-колонкой».

| | MongoDB | Postgres + JSONB |
|---|---|---|
| Модель | документ — единица хранения | строка + JSON-поле |
| Транзакции | на документ — атомарно всегда; между документами — с 4.0, только на replica set | обычные ACID |
| Индексы по вложенным полям | нативно | GIN по JSONB, expression-индексы |
| Шардирование | встроено (mongos, config servers) | нет из коробки (Citus, ручное) |
| Автоинкремент | нет | есть |
| Связи и JOIN | `$lookup`, ограниченно | полноценные |

## Что важно понимать

### Транзакции требуют replica set

Одиночный `mongod` не умеет multi-document транзакции. Даже в тестах поднимается replica set из одного узла — посмотри `testinfra.StartMongo`.

### `WithTransaction` повторяет твой код

Драйвер сам ретраит callback при транзиентных ошибках (конфликт записи, смена primary). Значит, всё внутри callback может выполниться **несколько раз**. Побочные эффекты вне базы (HTTP-запрос, отправка в брокер, инкремент счётчика в памяти) внутри транзакции — ошибка.

### Write concern и read concern

`w: 1` — подтвердил primary. `w: "majority"` — подтвердило большинство реплик. Read concern `majority` / `snapshot` — что ты увидишь при чтении. Значения по умолчанию менялись между версиями — не полагайся на них, а проверяй.

### Порядок без автоинкремента

В Mongo нет `SERIAL`. `ObjectID` упорядочен по времени, но только примерно (секунды + счётчик на клиенте). Для outbox, где порядок важен, нужен свой счётчик — и это создаёт горячую точку конкуренции. В задаче 04 ты столкнёшься с этим лично.

### Документ — это не доменная структура

Структура с `bson`-тегами и `_id` — это деталь хранилища. Вешать `bson`-теги на `domain.Order` — значит пускать инфраструктуру в домен.

## 🔎 Изучи сам

- BSON vs JSON
- embedding vs referencing — как выбирают
- `_id`, ObjectID — из чего состоит
- replica set, primary/secondary, election, oplog
- write concern, read concern, read preference

- aggregation pipeline
- change streams — и как они соотносятся с outbox
- TTL-индексы, partial-индексы, covered queries
