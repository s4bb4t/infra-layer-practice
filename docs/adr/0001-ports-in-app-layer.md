# 0001. Порты объявлены во внутреннем слое, в пакете internal/app/port

- Статус: Accepted
- Дата: 2026-10-17
- Шаг курса: 01 (пример заполненного ADR)

## Контекст

Сервис заказов должен работать с разными хранилищами (memory, Postgres, MySQL, Mongo) и брокерами (RabbitMQ, Redis Streams, Kafka, NATS) без изменений в бизнес-логике. Use case'ы должны тестироваться без контейнеров. В Go интерфейс принято объявлять на стороне потребителя, но потребителей у одного порта несколько: use case'ы, outbox relay, декораторы, контракт-тесты.

## Решение

Все интерфейсы, которые приложение требует от внешнего мира, объявлены в одном пакете `internal/app/port`. Пакет зависит только от `internal/app/domain`. Адаптеры в `internal/infrastructure/<tech>` импортируют `port` и `domain` и проверяют соответствие на этапе компиляции: `var _ port.OrderRepository = (*Orders)(nil)`.

## Рассмотренные альтернативы

### Интерфейсы рядом с каждым use case (consumer-side, идиоматичный Go)
- плюсы: каждый use case объявляет ровно те методы, что ему нужны (interface segregation); нет общего пакета, который «знает всё»;
- минусы: один и тот же `OrderRepository` повторяется в нескольких местах с разными наборами методов; контракт-тесту не на что сослаться как на единую спецификацию;
- почему не он: контракт-тесты — центральная идея проекта, им нужна одна спецификация на порт.

### Интерфейсы в `internal/app/domain`
- плюсы: ещё меньше пакетов;
- минусы: домен начинает знать про транзакции, outbox, кэш — то есть про существование инфраструктуры;
- почему не он: домен должен описывать бизнес-правила, а не то, как их хранят.

### Интерфейсы в пакете адаптера (provider-side)
- минусы: use case импортирует пакет адаптера, направление зависимостей разворачивается;
- почему не он: прямо противоречит тезису слоя.

## Последствия

- Видно одним файлом, что приложение требует от мира: это удобно на ревью.
- `port` может разрастись в «пакет всего». Держим правило: в `port` только интерфейсы и простые типы, которые нужны для их сигнатур (`DailySales`), без логики.
- Use case получает весь `OrderRepository`, даже если использует два метода. Принимаем ради единого контракта.

## Ответы на вопросы задачи

1. *Почему use case не импортирует ни одного драйвера?* Он зависит от `port.*`; конкретику выбирает `main.go`. Проверка: `go list -deps ./internal/app/... | grep -E 'pgx|mongo|kgo'` — пусто.
2. *Зачем `o.Version++` в `usecase.transition`?* … (заполняется менти)
